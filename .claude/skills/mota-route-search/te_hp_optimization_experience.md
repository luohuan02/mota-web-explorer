  「长程前置墙」）。只做降伤/省钥匙/换门/顺序重排 → 进入 zone-4 的状态只会严格更好（更多
  HP/钥匙/金币），zone-4 尾段（step~690 起）可原样保留。

- 方向：逐层审计「门后是否有必须打的高伤怪」；可避高伤就用替代路；黄钥匙富余时比较开门 vs MT28

- **路线族差异**（同族 walk 结构性对比 + 各自可优化点）：`te_hp_route_families.md`（39944
  全防 vs 4区2攻 的 +415 HP 纯分配对照；38624 弱 body 换 2420 反例）+ `te_hp_2420_funding_analysis.md`

## 关键证据：末段防商店 funding-critical + 魔龙 DEF 陡坡（2026-08-17 查实）

这是对「剩余方向」的重要校准：**zone1-3 省钥匙决策（D6/D7/D8 全部）是对的**，因为省下的 yk
在终局是「防商店 funding-critical」的稀缺资金，而非 stranded。完整推理见
`te_hp_zone1_decisions.md`「关键证据」；这里给结论 + 魔龙 DEF 陡坡：

- **最后一个 MT46 防商店（2120G，DEF 555→575）是 funding-critical**：靠 step973-976 MT28 卖 4 yk
  凑 400G（1773→2173）才买得起；没有它，魔龙 DEF 停在 572，伤 4676 vs 1336，**多 3340 血**。
  ⇒ 那 4 yk 边际值 ≈ **835 血/把**（不连续，只在 funding 阈值上成立；超出阈值的 yk 终局 stranded）。
- **魔龙 DEF 陡坡**：magicDragon atk=600 def=250 special=0 物理。pre-dragon DEF=592 → 伤 1336；
  DEF 599 → 伤 167（**+7 DEF 省 1169 血**）。但 39944 已买满 13 次防商店（MT32×8 + MT46×5）+
  全部 pre-dragon 防宝石 + MT2 specialTrader +17，**592 已 hard-cap**——除非找到漏收防宝石，
  否则魔龙 1336 是当前路线的固定下界（与「结构性封闭」点 5 一致，但从 DEF 侧证实）。
- **反向推论**：因防商店 near-dragon 值 1.58 HP/G（> 2420 商店 0.66），金币在「防商店未买满」时
  极其宝贵；一旦买满 13 次，剩余金币（终局 G=1707）全 stranded。**当前路线已按此最优排序**
  （防商店 > hp2000 > keyBundle+蓝瓶，见「结构性封闭」点 3 的 4420G 三者兼得目标）。

## Game 建模优化（钥匙-掉血权衡，供搜索）

当前 `Game.path_cost` 用 dmg 作主成本、钥匙作硬门，**不做 HP-vs-key 权衡**；用户的决策框架
（每条 = 「花 yk 免掉血」 vs 「花血省 yk」）无法被它自动评估。要建模，必须解决：

1. **yk 机会成本是不连续、终局决定的**，不是静态局部值：
   - 能凑够「下一档防商店 funding 阈值」的 yk → 边际值 ~835 血/把（由魔龙 DEF 陡坡决定）。
   - 超出的 yk → stranded ~0（终局 G=1707<2420，防商店已买满）。
2. **两阶段搜索**（避免 from-scratch 重搜墙）：
   - **阶段 A：终局金币闭环**——先解出防商店 funding 阈值序列（每次防商店需要的 G + 该商店的
     HP/G），得到「第 N 把 yk 值多少钱、值多少血」的分段阶梯函数。
   - **阶段 B：zone1-3 搜索**——把阶段 A 的阶梯函数反传为每把 yk 的机会成本，`path_cost` 里
     `spend_yk 的成本 = 100G × 当前 funding 档的 HP/G`，`save_yk 的收益 = 同`；门 vs 怪的比较
     用 `开门花费 = yk 边际值` vs `打怪花费 = dmg`。D6/D7/D8 的「翻面条件」就自动变成该阶梯
     函数落到某一档的判定，而不是手写常数阈值。
3. **安全不变式**：阶段 B 只改钥匙/金币/门/路选择，**不改 atk/def 购买**，因此 zone-4 尾段
   （step~690 起）与魔龙后资源可原样保留；改完仍走「离线 Game 重放 → web 复验 0 mismatch」。
4. **落地建议**：先在 `Game` 加一个 `key_opportunity_cost(gold_state, funding_table)` 辅助，
   输入终局 funding 表，输出当前每把 yk 的边际价值；再用它替换 `path_cost` 里钥匙硬门的判定为
   「开 vs 绕」软成本。回归用 `tests/run_strict_live_click_model_test.py` + `run_zone3_game_model_test.py`。

## 探索方法论（避免重复撞墙）

1. 先归因，再动手：任何「能不能省 X HP」先算清楚伤害来源（dmg 增量），别被 HP delta 骗。
2. 检查循环闸门：凡「道具 A→资源 B→道具 A」的闭环（魔龙/雪花/熔岩、MT44/upFly/魔法场），
   先确认是否结构性锁定，别在闭环上耗搜索。
3. 检查隐藏层/可达性：`HIDDEN_FLOORS`、`:next/:before` 跳过隐藏层、隐藏层只能特定道具到达——
   这些决定能否重排节点。
4. 检查物理 vs 魔法：`special=2` 才是魔攻（无视防御、可被神圣盾/magicImmune 减免）；其余是物理，
   靠 DEF。别把物理怪当魔法杠杆。
5. 一条 walk 是 ground truth（web 0 mismatch），搜索模型会骗人；改完必须离线 Game 重放 → web 复验
   （`scripts/live/live_zone3_mouse_replayer_cdp.js --target-click-only`，含金币 0 mismatch）。
6. 提升到 `best/` 需满足 skill 硬规则：可复现 walk + 终战前资源闭环审计（可达正 HP 收敛为 0、

## 16. yk/bk 边际汇率表 + 补血时点约束（2026-09-19 用户复盘，41400 实证）

**核心：yk 的边际价值不是固定 100/把，而是「该 yk 在最晚最佳替代点能换多少血」——替代点
汇率随路线浮动，早期花费必须打败最晚最佳汇率才划算。** 实测汇率（41301_vs_41228_compare.xlsx
逐层门/伤差异）：

| 兑现点 | 汇率 | 机制 |
|---|---|---|
| MT36 (6,2) 黄门 | **1yk ≈ 230 血** | 开门后绕开高伤怪群（41301 dmg528 vs 41228 758）；用户原话"34楼1yk换240"即此（笔误 34） |
| MT9 (5,9) 黄门 | 1yk ≈ 203 血 | vs 41228 开 MT9 蓝门烧 bk 的走法 |
| MT7 双门 (1,7)(3,7) | ~65 血/yk | 41228 不开省 2yk 但多扛 129 伤 |
| MT42 (4,5) 黄门 | 1yk ≈ 32 血 | 末端小收益 |
| 41F 对飞 | **1bk 级联 = 3yk** | z1 省 1bk → 41228 在 MT41 要开 3 黄门、41400 全省 |
| MT28 卖 yk | 100G/把 | 兜底汇率（最低档） |

**级联实例（41400 vs 41228 的钥匙侧来源）**：z1 省 1bk（不开 MT9 蓝门）→ 41F 对飞
省 3 yk + MT33 蓝门 +1yk/+75G + MT28 少卖 1yk → 合计 5 yk 优势 → 兑现在 MT7×2、MT9×1、
MT36×1（≈230）、MT42×1。**若 41228 血统能在别处省 1 yk，即可开 MT36(6,2) 门换 ≈230 血。**

**补血时点约束（钥匙路线选择必须在「后续补血点的 yk 需求」下评估）**：z2 拿 MT19 蓝钥匙
两条路——MT12 开 (3,10) 门打兽人（zombie，-81 血，净 +3yk+1bk）vs MT15 开 (1,4) 门打高级
法师（少掉血，净 +1yk+1bk）。MT15 补血点需要 yk：路线 B 血省但 yk 不够补血，要么掉血补血
要么额外找 yk，都额外费血。**41400 的实际解：先打 MT12（[518]），MT15(1,4) 延后（[630]）**
——用户原话「15 楼看起来掉血少，但少吃 1yk 导致后面差 yk，先打 12 反而更优，15 延后到 4 区
的时候打」。选择价值依赖未来时点，不要在抉择点就地定价。

**存活余量耦合的可选资源（实测 2026-09-19）**：41304-z1 走廊 [211-216] = 到达 MT6(6,1) →
auto_sweep 顺打 MT6(7,1) bluePriest（法师）→ 开 (11,2) 门 → bat → auto 拿 x8y3 redPotion(+50)。
**删显式法师击杀步无效（到达 sweep 已打）**；删蝙蝠/走廊在 MT7(9,7) 断裂（走廊 yk 是下游刚需，
 corridor 结构性）。**10F boss 入场 hp=325、战损 304、余量仅 21**；用户探索：不打法师时余量
差 ~7 血 → 血瓶被强制。**若前面省 7+ 血 → 走廊可绕 → 净省 20+ 血。可选性由 boss 余量解锁，
余量是别的优化的函数。** 同理 z1 MT6 法师+小蝙蝠血瓶 vs MT11(7,7)/MT16(8,2) 开门拿
bigSlime+100 血：开门费 yk（对 MT36 汇率 ~230 亏），故选打架。

**MT47 门集合重排 = 中性**（2026-09-19 修正）：41400 的 z5 MT47 门差异 (11,7) vs (8,4) 终态
门集合等价、dmg 相同，**不是收益点**。41400 的全部收益来自 z2 少杀 3 战的资源集裁剪。

**对搜索器的教训**：资源收集集不是固定量——"资源闭环=0"是错误公理。当采集成本（为拿资源
进的战斗+钥匙）> 资源终局边际价值时，少收更优（41400 的 3 场 redPriest/blackSlime）。搜索算子
需要"依赖感知消融"：消融区域后对依赖断裂步尝试替代满足（替代门/替代拾取点）。用户实机录像
（z1 +3、z2 -99）是发现这类重构的唯一已证探针。
